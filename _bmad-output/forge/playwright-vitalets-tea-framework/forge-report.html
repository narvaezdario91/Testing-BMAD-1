Forge Session Report

Framework de Automatización Playwright BDD (vitalets) + SOLID + Metodología TEA

Proyecto: AI_Testing_BMAD_1 • Usuario: Dario

🔒 Decisiones Arquitectónicas Blindadas (Locks)

1. Inversión de Dependencias (DIP) y Modularidad (SRP)

Se utiliza el motor nativo de fixtures de Playwright (test.extend) en playwright-bdd para la inyección limpia de dependencias. Se reemplazan los Page Objects monolíticos por Component/Domain Objects atómicos y reutilizables.

2. Gestión de Estado y Datos (ScenarioContext + Network-First)

Estado entre pasos gobernado por un fixture scenarioContext fuertemente tipado por worker. Preparación ágil de precondiciones en Given vía API nativa (playwright.request), reservando la UI para la acción real bajo prueba (When).

3. Estructura de Proyecto y Gobernanza de Tags TEA

Layout desacoplado en capas (features/, steps/, fixtures/, domain/components/, domain/services/, support/). Ejecución de Quality Gates gobernada por tags de severidad (@P0, @P1, @P2, @story).

4. Localización Resiliente y Web-First Assertions (Cero Flakiness)

Prioridad estricta en User-Facing Locators (getByRole, getByLabel, getByTestId) y Web-First Assertions con auto-waiting. Prohibición total de waitForTimeout arbitrarios y recolección automática de trazas en fallos.

5. Integración con el Ecosistema TEA de BMAD

Scripts NPM unificados (bdd:gen, test:p0, test:p1, test:all) y exportación de reportes hacia _bmad-output/test-artifacts/ para automatizar la Matriz de Trazabilidad (bmad-testarch-trace) y el ciclo ATDD.

🚫 Opciones Rechazadas y Trade-offs

Screenplay Pattern Clásico (Actors / Tasks / Abilities)

Razón de descarte: Genera alta sobrecarga de ceremonia y duplica innecesariamente capas que ya resuelven Gherkin + Fixtures nativos de Playwright.

Page Object Model Monolítico Tradicional

Razón de descarte: Genera "God Classes" que violan el principio de responsabilidad única (SRP) y colisionan con el ciclo de vida de los fixtures.

World / State Bag Dinámico no Tipado (Clave-Valor)

Razón de descarte: Destruye la seguridad de tipos de TypeScript y provoca fugas de estado en ejecuciones paralelas multihilo.

Wrappers Customizados con Pausas Fijas (sleep / waitForTimeout)

Razón de descarte: Anula el auto-waiting nativo de Playwright y es la causa #1 de inestabilidad y tests flaky en CI/CD.
